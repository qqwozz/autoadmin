# AutoAdmin — Идея проекта

## Платформа управления расписанием на базе Telegram
### (для репетиторов, фотографов и специалистов)

---

## 1. Цель проекта

Разработать Telegram-платформу, где **мастер** управляет расписанием через бота, а **клиенты** записываются, переносят и уточняют детали встреч.

**Ключевые особенности:**
- Клиент **привязывается к мастеру** только по **короткому ID** или **QR-коду**.
- Реализована **защита от неявок (no-show)**.
- Бизнес-модель — **подписка** для мастеров.
- Технологии: **Python** (Telegram-бот) + **Golang** (бэкенд, БД).

---

## 2. Архитектура

| Компонент | Технология | Задачи |
|-----------|------------|--------|
| Telegram-бот | Python (aiogram 3.x) | Диалоги, кнопки, состояния |
| Бэкенд | Golang | Расписание, подписки, защита от неявок |
| База данных | SQLite | Хранение всех данных |
| Админ-панель | Golang + HTML | Управление тарифами, просмотр логов |

> **Взаимодействие:** Python-бот → Go-бэкенд через REST API (JSON).

---

## 3. Роли и возможности

### 3.1. Клиент

**Привязка к мастеру (только 2 способа):**
- Вводит **короткий ID** мастера (например `REP-4281`)
- Сканирует **QR-код** мастера

**После привязки:**
- Просмотр свободных слотов (день / неделя)
- **Запись** на время
- **Перенос** записи
- **Отмена** записи
- Уточнение деталей (текст, фото, голосовые)
- Получение уведомлений

**Привязка к нескольким мастерам** — разрешена.

### 3.2. Мастер

**Регистрация и вход:**
- Через Telegram
- Автоматическая генерация:
  - Короткого ID (`REP-4281`)
  - QR-кода

**Функционал (после активации подписки):**

| Функция | Описание |
|---------|----------|
| Просмотр расписания | Сегодня / завтра / неделя / след. неделя |
| Управление встречами | Перенос, отмена |
| Детали встречи | Комментарии, файлы |
| Настройки | Рабочие часы, перерывы |
| Мои клиенты | Список с историей |
| Управление подпиской | Покупка, продление |
| **Защита от неявок** | Настройка подтверждения, штрафов, чёрный список |

**Уведомления мастера:**
- Новая запись
- Отмена / перенос клиентом
- Напоминание за 1 час
- Клиент не пришёл (no-show)
- За 3 дня до окончания подписки

## 5. Защита от неявок (no-show)

**Проблема:** клиент записался, но не пришёл → мастер теряет время и деньги.

### 5.1. Механизм «подтверждение записи»

| Этап | Действие | Тайминг |
|------|----------|---------|
| 1 | Клиент записывается | Сразу |
| 2 | Бот присылает **код подтверждения** (4 цифры) | Сразу |
| 3 | Клиент должен отправить этот код в бот | В течение 15 минут |
| 4 | Если код не отправлен → слот освобождается | Через 15 минут |

**Код подтверждения выглядит так:**
```
✅ Вы записаны на 15 мая в 14:00.
Для подтверждения отправьте код: 4823
Код действителен 15 минут.
```

### 5.2. Штрафные санкции (настраиваются мастером)

| Опция | По умолчанию | Описание |
|-------|--------------|----------|
| Включить штрафы | Да | Мастер может отключить |
| Размер штрафа | 50% стоимости встречи | Клиент должен оплатить до следующей записи |
| Блокировка после N неявок | 3 неявки | Временная блокировка на 30 дней |
| Чёрный список | Вручную | Мастер может добавить клиента вручную |

### 5.3. Алгоритм обработки неявки

1. Наступает время встречи
2. Клиент не появился (бот не получил отметки)
3. Бот через 15 минут пишет мастеру: *«Клиент не пришёл, отметить как неявку?»*
4. Мастер подтверждает → система:
   - Увеличивает счётчик неявок клиента
   - Если достигнут лимит → блокировка записей
   - Начисляет штраф (если включён)
   - Отправляет клиенту уведомление

### 5.4. Отметка о приходе (для клиента)

**Два варианта реализации (на выбор мастера):**

| Вариант | Как работает |
|---------|--------------|
| **Автоматический** | Клиент отправляет геопозицию в радиусе 100 м от адреса мастера |
| **Ручной** | Клиент нажимает кнопку «Я пришёл» за 15 минут до или через 15 минут после начала |

### 5.5. Таблица статусов записи

| Статус | Значение |
|--------|----------|
| `pending_confirmation` | Ожидает подтверждения по коду |
| `confirmed` | Подтверждена |
| `completed` | Клиент пришёл |
| `no_show` | Неявка (зафиксирована) |
| `cancelled` | Отменена клиентом |
| `cancelled_by_master` | Отменена мастером |

## 6. Система подписок

### 6.1. Тарифы (пример)

| Тариф | Стоимость | Лимит встреч/мес | Лимит клиентов |
|-------|-----------|------------------|----------------|
| Базовый | 300 ₽ | 30 | 10 |
| Про | 700 ₽ | 100 | 50 |
| Безлимит | 1500 ₽ | ∞ | ∞ |

### 6.2. Логика работы

1. Мастер выбирает тариф в боте → оплата (Telegram Stars / ЮKassa)
2. После оплаты → подписка активна 30 дней
3. За 7, 3 и 1 день до окончания → уведомления
4. При окончании → только чтение расписания, новые клиенты не привязываются

## 7. Пользовательские сценарии (с защитой от неявок)

**Сценарий 1. Клиент записывается и подтверждает:**
1. Клиент вводит ID мастера `REP-4281`
2. Выбирает слот → нажимает «Записаться»
3. Бот присылает код `4823`
4. Клиент отправляет код в бот
5. Статус → `confirmed`, мастер получает уведомление

**Сценарий 2. Клиент не подтвердил запись:**
1. Клиент записался, но не отправил код
2. Через 15 минут бот освобождает слот
3. Слот снова доступен для других клиентов
4. Клиент получает: *«Запись не подтверждена, слот освобождён»*

**Сценарий 3. Клиент не пришёл:**
1. Встреча в 14:00
2. В 14:15 клиент не нажал «Я пришёл»
3. Мастер получает кнопку «Отметить неявку»
4. Мастер нажимает → клиент получает штраф
5. Если неявок ≥ 3 → клиент заблокирован на 30 дней

**Сценарий 4. Заблокированный клиент пытается записаться:**
1. Клиент вводит ID мастера
2. Бот пишет: *«Вы временно заблокированы за неявки. До разблокировки: 15 дней»*
3. Запись невозможна
